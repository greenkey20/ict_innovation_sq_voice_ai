# 노트북 리뷰 (학습 내용 정확성 검토)

사용자가 넘긴 인자(파일명)의 노트북을 같은 폴더의 `_강사님` 버전과 비교해서, **틀렸거나 오해를 부를 수 있는 내용**을 찾는다. 사용자는 이 저장소의 노트북 설명으로 공부하므로 틀린 설명은 그대로 학습된다(CLAUDE.md "Knowledge accuracy").

## 지켜야 할 컨벤션 (CLAUDE.md 요약)

- 노트북 이름은 한글이고 변형이 있다: plain(작업 사본), `_강사님`(강사님 원본), `_은영 수업`(수업 중 직접 작성한 사본), `_Load`(저장 모델 불러오기).
- **`_강사님` 파일은 절대 수정하지 않는다.** 비교 대상으로만 읽는다. 수정 제안은 plain 또는 `_은영 수업` 학습 파일에만 한다.
- 학습 파일의 **코드는 사용자가 요청하기 전에는 바꾸지 않는다.** 이 스킬은 기본적으로 "지적과 제안"까지만 하고, 노트북은 고치지 않는다.
- 경로는 노트북 폴더 기준 상대경로(`../dataset/...`, `../models/...`)다.
- 환경은 **`voice-ai` conda(Python 3.11, `/opt/anaconda3/envs/voice-ai/bin/python`)만** 쓴다. numpy 1.26.4 유지(TensorFlow 2.16). 패키지가 없으면 임의로 설치하지 말고 `개발환경_이슈노트.md`를 확인한 뒤 사용자에게 알린다. 설치가 필요하면 `!pip`가 아니라 `%pip install`을 안내한다.
- 노트북 JSON(base64 이미지·오디오 포함)을 `cat`/`Read`로 통째로 읽지 않는다. 아래 "읽는 방법"의 Python으로 셀 소스와 텍스트 출력만 꺼낸다.

## 수행 순서

1. **대상 찾기.** 인자로 받은 파일명으로 저장소에서 노트북을 찾는다(정확히 일치 → 부분 일치 순, 여러 개이거나 없으면 사용자에게 묻는다).
   - 인자가 `_강사님` 파일이면 "강사님 파일은 비교 기준이라 수정 대상이 아님"을 알리고, 어느 학습 파일을 검토할지 묻는다.
   - 같은 폴더에서 `_강사님`이 붙은 짝을 찾는다. 이름 규칙이 조금 다를 수 있다(예: `017_sound/03_FFT_STFT_그림으로_소리읽기.ipynb`의 짝은 `…_Ver3_실제음성정리_강사님.ipynb`). 파일명에 `강사님`이 들어간 것 중 앞부분이 같은 것을 찾고, **짝이 없으면 없다고 말하고 학습 파일 단독 검토로 진행**한다.
   - 노트북 파일을 찾는 코드에서 `glob(...)[0]`처럼 순서에 기대지 말고, 항상 **정확한 파일명**을 지정한다(같은 접두어 파일이 둘 이상일 수 있다).
2. **기존 기록 읽기.** `학습내용_검증기록.md`를 읽어 이미 고쳐진 오류(1.1표)와 아직 확정하지 못한 항목(2번 표)을 파악한다. 같은 내용을 다시 틀리게 설명하지 않도록, 그리고 같은 지적을 중복 기록하지 않도록 한다.
3. **두 노트북 읽기.** 아래 Python으로 셀 목록(번호, 종류, 소스, 텍스트 출력 일부)을 출력해서 읽는다.
4. **비교하고 검토한다.**
   - 셀 단위로 맞춘다(소스 유사도). "강사님에만 있음 / 내 파일에만 있음 / 달라진 셀"을 구분한다.
   - 코드는 주석을 뺀 형태로도 비교한다. 코드가 같은데 설명만 다른지, 코드까지 다른지 구분한다.
   - 내 파일의 **설명(마크다운·주석)** 중 사실과 다르거나 오해하기 쉬운 것을 찾는다. 강사님 설명과 다른 경우 **어느 쪽이 맞는지는 근거로 판단**한다.
   - 근거 없이 단정하지 않는다. 가능하면 **직접 실행해서 확인**한다(`voice-ai`의 Python으로 작은 예제 실행). 논문 내용은 `012_transformer/transformer.pdf`와 대조한다. 실행하지 못한 것은 "추정"으로 표시한다.
   - **실행하면 안 되는 것:** 비용이 드는 API 호출 셀(013 이후 OpenAI/Anthropic/SerpAPI), 오래 걸리는 학습, 패키지 설치, `.env`를 읽거나 쓰는 코드.
5. **결과를 보고한다(한국어, chat).** 문제별로 `위치(셀 번호)`, `무엇이 문제인지`, `근거(실행 결과/출처)`, `고친다면 어떻게`를 적는다. 확인하지 못한 것은 "미확인"이라고 쓴다.
6. **기록한다.**
   - 문제가 **있으면** `학습내용_검증기록.md`에 항목을 추가한다.
     - 직접 확인해서 틀린 것이 확정된 경우: 1.1표와 같은 형식(`위치 | 문제 | 올바른 내용 | 고친 곳`)으로 새 날짜 소절을 만들어 적고, "고친 곳"에는 아직 수정 전이면 `제안만(미수정)`이라고 쓴다.
     - 확정하지 못한 경우: 2번 표와 같은 형식(`내용 | 상태 | 이유`)으로 **`미확인`** 이라고 표기해서 추가한다.
     - 날짜는 시스템이 알려 준 오늘 날짜를 쓴다. 파일 안의 "점검 방법과 한계" 문단 앞에 새 소절을 넣는다.
   - 문제가 **없으면** 파일은 건드리지 않고 `이상 없음`이라고 출력한다(어떤 범위를 어떻게 확인했는지 한 줄 덧붙인다).
7. 커밋은 하지 않는다(커밋은 `/커밋준비` 스킬에서 사용자 승인 후).

## 읽는 방법 (노트북 JSON을 통째로 읽지 않기)

```bash
/opt/anaconda3/envs/voice-ai/bin/python - <<'PYEOF'
import json,sys
fn = "<정확한 노트북 경로>"
nb = json.load(open(fn, encoding="utf-8"))
print("cells", len(nb["cells"]), "| kernelspec", nb["metadata"].get("kernelspec", {}).get("name"))
for i, c in enumerate(nb["cells"]):
    s = "".join(c["source"])
    if not s.strip():
        continue
    print("=====", i, c["cell_type"], c.get("execution_count"))
    print(s[:1500])
    for o in c.get("outputs", []):
        if o["output_type"] == "stream":
            print("--out:", "".join(o["text"])[:500])
        elif o["output_type"] == "error":
            print("--ERR", o["ename"], o["evalue"][:200])
        else:
            print("--", o["output_type"], list(o.get("data", {})))   # 이미지/오디오는 종류만 표시
PYEOF
```

## 주의

- 강사님 파일을 열어서 비교만 하고, **저장하거나 메타데이터도 건드리지 않는다.** (kernelspec 정규화는 과거에 한 번 한 일이며 반복하지 않는다.)
- 학습 파일에 대한 수정은 **제안**으로만 적고, 사용자가 "고쳐 줘"라고 할 때 적용한다. 적용할 때도 코드는 바꾸지 않고 설명(주석·마크다운)을 고치는 것이 기본이다.
- 기록 파일에는 API 키, 개인 경로(`/Users/...`)를 쓰지 않는다.
