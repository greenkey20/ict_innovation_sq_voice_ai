## Git / 저장소 관리 정책

### 이 저장소에 올리지 않는 것 (`.gitignore`로 제외)

- `model/`, `model1006/`, `*.keras` (현재 `models/` 아래에 위치) — 학습된 모델 체크포인트. 재학습으로 재생성 가능하고, 개수가 많고(수백 개) 용량이 커서(개별 파일 최대 290MB — GitHub의 파일당 100MB 하드 제한을 이미 초과) git으로 관리하지 않습니다.
- `*.weights`, `*.pt` — 사전학습 모델 가중치 (예: `yolov3.weights` 약 248MB는 100MB 제한 초과, `yolov8n.pt`는 라이브러리가 자동 다운로드).
- `.env` — API 키 등 비밀 값 (저장소 루트, 하위 폴더 포함 전체 제외). 이 저장소는 public이라 실수로 올라가면 키가 노출되므로 새 키 파일을 만들 때도 `git check-ignore -v <파일>`로 확인하세요.
- `dataset/aclImdb/`(IMDB 약 203MB·파일 5만 개), `dataset/glove.6B/`(GloVe 약 2.1GB) — 용량이 큰 외부 데이터셋. 직접 내려받아 `dataset/` 아래에 두고 사용합니다.
- `.ipynb_checkpoints/`, `__pycache__/`, `.DS_Store` — Jupyter/Python/macOS 캐시성 파일
- `.vscode/` — VS Code 개인 설정(인터프리터 경로 등 컴퓨터별 설정), `Untitled*.ipynb` — 임시 연습용 노트북
- `017_sound/data/`, `017_sound/results/` — **내 목소리 녹음**(`my_voice*.wav`, `data/drafts/`)과 결과 캡처. 공개 저장소라서 올리지 않습니다. 강사님이 제공한 합성음 `tone_sequence_*.wav`도 이 폴더에 있어 함께 제외됩니다.

### `.git/hooks/pre-commit` 안전장치

100MB 넘는 파일이 실수로 스테이징되면 커밋 자체를 로컬에서 차단하는 훅이 설치돼 있습니다 (저장소를 새로 clone하면 훅은 포함되지 않으므로, 다른 컴퓨터에서 이어서 작업할 경우 동일한 훅을 다시 만들어두는 걸 권장합니다).

### 새 파일(특히 모델/데이터)이 생길 때마다 체크리스트

1. `du -sh <새 폴더/파일>`로 용량 확인
2. 100MB를 넘거나 재학습으로 재생성 가능한 산출물이면 → `.gitignore`에 패턴 추가
3. `git status`로 의도치 않게 큰 파일이 걸리지 않았는지 확인 후 커밋
4. 모델 체크포인트 중 "이것만은 꼭 보존하고 싶다"는 게 생기면, 체크포인트 폴더 전체를 올리지 말고 `models/model1001/best/`처럼 정말 필요한 1~2개 파일만 Git LFS로 추적 (`git lfs track "models/model1001/best/*.keras"`) — 전체 체크포인트를 LFS에 올리는 것은 여전히 지양 (무료 LFS 용량 한도를 빠르게 소진함)

### 노트북 출력(이미지) 포함 여부

`matplotlib` 그래프 등 셀 실행 결과가 그대로 저장된 노트북(`Keras code.ipynb` 등)은 용량이 커질 수 있지만(수 MB), GitHub가 `.ipynb`를 열람할 때 출력까지 렌더링해줘서 복습하기 좋으므로 **기본적으로 출력 포함 상태를 유지**합니다. 용량이 계속 신경 쓰이면 `nbstripout` 같은 도구로 커밋 전 출력만 제거하는 방법도 있습니다.

단, **내 목소리·강사님 목소리 같은 음원 재생기(Audio 출력)** 와 `/Users/…` 같은 **내 컴퓨터 경로**가 출력에 들어 있으면 공개 저장소에서 누구나 보고 들을 수 있으므로 커밋 전에 제거합니다(합성음 재생기는 괜찮지만 GitHub 노트북 뷰어는 재생하지 못합니다). `.claude/skills/commit-prep`의 점검 스크립트(`scan_notebook_outputs.py`)로 확인할 수 있습니다.

### 커널을 고르면 생기는 메타데이터 변경

VS Code나 Jupyter에서 노트북을 열고 커널을 선택/저장하면 `.ipynb` 안의 커널 정보(`kernelspec`)와 파이썬 버전 표기(`language_info.version`)가 바뀌어서, 코드는 그대로인데 `git status`에 변경 파일로 뜰 수 있습니다. 노트북은 모두 `voice-ai` 커널로 저장해 두었지만, VS Code가 `name`을 `python3`로 다시 쓰는 경우가 있습니다.

- 커밋 전에 `git status`로 **메타데이터만 바뀐 파일**을 확인하고, 내용 변경 커밋에 섞이지 않게 합니다 (필요하면 `git checkout -- <파일>`로 되돌리기).
- 노트북 변경 내역은 `git diff` 대신 VS Code의 노트북 diff로 보면 셀 단위로 읽기 편합니다. 자세한 설정과 배경은 `개발환경_이슈노트.md` #8 참고.
