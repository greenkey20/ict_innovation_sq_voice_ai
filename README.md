# ICT 혁신 스퀘어 — AI/딥러닝 수업 노트북 모음

ICT 혁신 스퀘어 AI(Voice AI) 과정에서 다루는 Jupyter 노트북, 실습 데이터셋, 학습 결과물을 버전관리하기 위한 저장소입니다.

## 실행 환경

- **conda 가상환경 `voice-ai` (Python 3.11)만 사용합니다.** 이 머신의 다른 conda 환경(`base`, `tf_env`, `study` 등)은 이 수업과 무관합니다.
- 노트북 실행 전 커널이 `voice-ai`로 선택돼 있는지 확인하세요. 노트북 안에서 직접 확인하려면:
  ```python
  import sys; print(sys.executable)
  # /opt/anaconda3/envs/voice-ai/bin/python 이 나와야 정상
  ```
- Jupyter는 **저장소 루트에서 실행**하세요 (`jupyter notebook` / `jupyter lab`). `dataset/`, `model/` 등에 대한 상대경로와 `import mat_kor`가 루트 기준으로 동작합니다.

## Git / 저장소 관리 정책

### 이 저장소에 올리지 않는 것 (`.gitignore`로 제외)

- `model/`, `model1006/`, 최상위 `*.keras` — 학습된 모델 체크포인트. 재학습으로 재생성 가능하고, 개수가 많고(수백 개) 용량이 커서(개별 파일 최대 290MB — GitHub의 파일당 100MB 하드 제한을 이미 초과) git으로 관리하지 않습니다.
- `.ipynb_checkpoints/`, `__pycache__/`, `.DS_Store` — Jupyter/Python/macOS 캐시성 파일

### `.git/hooks/pre-commit` 안전장치

100MB 넘는 파일이 실수로 스테이징되면 커밋 자체를 로컬에서 차단하는 훅이 설치돼 있습니다 (저장소를 새로 clone하면 훅은 포함되지 않으므로, 다른 컴퓨터에서 이어서 작업할 경우 동일한 훅을 다시 만들어두는 걸 권장합니다).

### 새 파일(특히 모델/데이터)이 생길 때마다 체크리스트

1. `du -sh <새 폴더/파일>`로 용량 확인
2. 100MB를 넘거나 재학습으로 재생성 가능한 산출물이면 → `.gitignore`에 패턴 추가
3. `git status`로 의도치 않게 큰 파일이 걸리지 않았는지 확인 후 커밋
4. 모델 체크포인트 중 "이것만은 꼭 보존하고 싶다"는 게 생기면, 체크포인트 폴더 전체를 올리지 말고 `model/best/`처럼 정말 필요한 1~2개 파일만 Git LFS로 추적 (`git lfs track "model/best/*.keras"`) — 전체 체크포인트를 LFS에 올리는 것은 여전히 지양 (무료 LFS 용량 한도를 빠르게 소진함)

### 노트북 출력(이미지) 포함 여부

`matplotlib` 그래프 등 셀 실행 결과가 그대로 저장된 노트북(`Keras code.ipynb` 등)은 용량이 커질 수 있지만(수 MB), GitHub가 `.ipynb`를 열람할 때 출력까지 렌더링해줘서 복습하기 좋으므로 **기본적으로 출력 포함 상태를 유지**합니다. 용량이 계속 신경 쓰이면 `nbstripout` 같은 도구로 커밋 전 출력만 제거하는 방법도 있습니다.
