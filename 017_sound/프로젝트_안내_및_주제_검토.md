## 4. 평가와 코멘트

### 4.1 강사님 기준과의 적합성
- **OpenAI API 기반** 범주에 들어갑니다. 수업 `013_openai_api`에서 이미 **STT(`transcribe_korean`)와 TTS(`text_to_wav`)** 를 다뤘고 **license-key가 제공**됩니다 **[확인]**.

- **위험:** 외부 서비스(발음 평가 API, 음악 인식 API, 가사 API, 음악 카탈로그 API)는 **제공되는 키가 없고 약관·요금·지원 언어가 불확실**합니다. 40시간에서 **키 발급과 약관 확인에만 시간이 새기 쉽습니다.** 필수 기능은 **수업에서 제공받는 OpenAI API만으로** 동작하도록 설계하는 것을 권합니다 **[추정]**.

### 4.2 아이디어의 강점
- **문제의 출처가 분명**합니다(좋아하는 노래의 뜻을 알고 따라 부르고 싶다). 발표에서 "왜 만들었나"를 설명하기 쉽습니다.
- **듣기(TTS → 받아쓰기)와 말하기(녹음 → STT) 두 가지 음성 활용**을 모두 쓰고, 수업의 STT·TTS·WER/CER·음향 처리(017)와 겹칩니다.
- 장표의 포트폴리오 목적(경험 증명, 개발 프로세스 이해)에 맞춰 **"실험과 평가를 포함한 음성 AI 프로젝트"** 로 만들 수 있습니다.

### 4.3 위험과 해결 방향
| 위험 | 설명 | 해결 방향 |
|---|---|---|
| **데이터(가사) 확보 + 저작권** | 가사와 음원은 저작권 대상일 수 있음. 이 저장소는 공개 | **직접 만든 예문**, 공개·자유 이용이 확인된 문장으로 시작. 상업 가사/음원은 **저장소·발표 자료에 넣지 않음**. "개인 학습용 입력 기능"으로만 두는 안은 약관을 확인한 뒤 판단 |
| **STT 일치 ≠ 발음 정확** | STT는 문맥으로 의도한 문장을 맞힐 수 있음 | 채점 지표를 **"단어 일치도(WER/CER)"** 로 이름 붙이고 "발음 평가"라고 주장하지 않음 |
| **범위 초과** | 검색·가사·TTS·받아쓰기·녹음·평가·PWA를 모두 넣음 | MVP를 **핵심 흐름 하나**로 제한(아래 4.4) |
| **채점의 정의** | 점수의 의미가 모호함 | 단어 일치도 / 발음 정확도 / 노래 실력을 **구분**해서 앞의 둘만 다룸 |
| **API 의존** | 한도·키·모델 이름이 바뀔 수 있음 | 수업 키로 **1일차에 실제 호출 테스트**, 대체 경로(직접 입력, 녹음 파일 업로드) 준비 |

### 4.4 제안 MVP (노래 기능은 모두 확장)
```text
[입력] 학습 문장 선택/입력 (직접 만든 예문, 사용 권한이 확인된 문장)
   │
   ├─ 학습 1 (듣기): OpenAI TTS로 재생 → 사용자가 받아쓰기 → 정답과 비교해 WER/CER·틀린 단어 표시
   │
   └─ 학습 2 (말하기): 사용자가 문장을 읽어 녹음 → STT로 인식 → 기준 문장과 WER/CER 비교
[추가 실험 1개] TTS 음성과 내 녹음의 차이를 파형·길이·SR·Mel로 비교 (수업 017 연결)
[확장] 노래 검색(텍스트) → 소리 검색 → 노래 채점
```
- **받아쓰기(학습 1)** 는 외부 STT가 없어도 되고, 키보드 입력을 정답과 비교하는 것이라 **가장 안전한 핵심 기능**입니다 **[추정]**.

### 7.3 WER·CER 한눈에 (직접 구현·실행해 확인한 것)
**정의**
- 정답(reference)과 인식 결과(hypothesis)를 비교해 **최소 수정 횟수**(Levenshtein 편집 거리)를 셉니다 **[일반 지식]**.
  - **S** 치환(바뀜), **D** 삭제(빠짐), **I** 삽입(더 붙음), **N** 정답의 전체 단위 수
  - **오류율 = (S + D + I) ÷ N**
- **WER**(Word Error Rate)은 **단어 단위**, **CER**(Character Error Rate)은 **글자 단위**입니다. 한국어에서 "단어"는 보통 **띄어쓰기로 나뉜 어절**로 셉니다(제 구현 기준).
- 0에 가까울수록 정확합니다. 삽입이 많으면 **1을 넘을 수도** 있습니다 **[일반 지식]**.

**손계산 예 (직접 계산해 확인)**
| 정답 | 인식 | WER | CER (공백 제외 글자) |
|---|---|---|---|
| 오늘 날씨가 좋아요 | 오늘 날씨 좋아요 | **1/3 = 0.333** (치환 1: 날씨가→날씨) | **1/8 = 0.125** (삭제 1: '가') |
| 오늘 날씨가 좋아요 | 오늘 날씨가 좋아요 | 0 | 0 |
| 오늘 날씨가 좋아요 | 내일 날씨가 정말 좋아요 | 2/3 = 0.667 (치환 1 + 삽입 1) | 4/8 = 0.5 (치환 2 + 삽입 2) |
- **한국어에서 WER과 CER이 크게 다른 이유**: 조사·어미가 어절에 붙어 있어서 **'날씨가' → '날씨'** 처럼 한 글자만 달라도 **어절 하나가 통째로 틀린 것**이 됩니다. 그래서 **CER이 더 세밀한 지표**이고, 한국어 평가에서는 **CER을 함께 보는 것**이 좋습니다 **[제 판단, 일반적인 관행 여부는 미확인]**.

**꼭 정하고 가야 하는 규칙: 정규화(비교 전에 문장을 같은 모양으로 맞추기)**
- Whisper는 **쉼표를 마음대로 넣습니다.** 정규화 없이 비교하면 **같은 문장인데도 틀린 것으로 셉니다.** 아래 5개 WAV로 직접 확인한 결과입니다.

**실제 결과 (이 저장소 `data/speech/`의 WAV 5개를 Whisper tiny(int8, 한국어, `beam_size=1`)로 인식 → `speech_manifest.json`의 정답과 비교)**
| ID(끝 4자리) | 인식에서 달라진 곳 | WER (구두점 제거 후) | CER |
|---|---|---|---|
| 0001 | 없음 (정답과 동일) | 0.000 | 0.000 |
| 0006 | 쉼표만 추가 | **0.000** | 0.000 |
| 0008 | `자료의`→`자료에`, 쉼표 추가 | 0.059 | 0.021 |
| 0012 | `알맞은`→`알마진`, 쉼표 추가 | 0.077 | 0.056 |
| 0014 | `쉬었다가`→`수였다가`, 쉼표 추가 | 0.250 | 0.167 |
| **5개 합산** | | **0.060 (3/50)** | **0.034 (5/146)** |
- **구두점을 지우지 않고 그대로 비교하면 같은 5개의 합산 WER이 `0.200`(10/50)** 으로 나옵니다(쉼표 붙은 어절을 "다른 단어"로 세기 때문). **정규화 규칙에 따라 점수가 3배 이상 달라진다**는 뜻입니다.
- 이 5개는 **수업에서 제공한 음성(깨끗한 발음)** 이라 결과가 좋은 편입니다. **내 목소리·소음·빠른 말에서는 달라질 수 있습니다(미확인)**.
- 실행에 쓴 별도 스크립트는 이 저장소 노트북에 넣지 않았습니다(아래 코드가 같은 계산).

**직접 구현 코드(검증함, 약 20줄)**
```python
import re
def edit_distance(ref, hyp):
    """Levenshtein 거리와 (S 치환, D 삭제, I 삽입) 개수를 함께 구함"""
    n, m = len(ref), len(hyp)
    dp = [[(0,0,0,0)]*(m+1) for _ in range(n+1)]          # (총비용, S, D, I)
    for i in range(1,n+1): dp[i][0] = (i,0,i,0)
    for j in range(1,m+1): dp[0][j] = (j,0,0,j)
    for i in range(1,n+1):
        for j in range(1,m+1):
            if ref[i-1]==hyp[j-1]: dp[i][j] = dp[i-1][j-1]
            else:
                c,s,d,ins = dp[i-1][j-1]; sub  = (c+1,s+1,d,ins)
                c,s,d,ins = dp[i-1][j];   dele = (c+1,s,d+1,ins)
                c,s,d,ins = dp[i][j-1];   inse = (c+1,s,d,ins+1)
                dp[i][j] = min(sub,dele,inse)
    return dp[n][m]

normalize = lambda t: re.sub(r'[.,!?~\-]', '', t).strip()   # 구두점 제거 (규칙은 직접 정해야 함)
def wer(ref, hyp):
    r, h = normalize(ref).split(), normalize(hyp).split()
    return edit_distance(r, h)[0] / len(r)
def cer(ref, hyp):
    r, h = list(normalize(ref).replace(' ','')), list(normalize(hyp).replace(' ',''))
    return edit_distance(r, h)[0] / len(r)
```
- 라이브러리로는 `jiwer`가 널리 쓰인다고 알고 있으나 **이 환경(`voice-ai`)에는 설치되어 있지 않고 직접 확인하지 않았습니다 [일반 지식, 미확인]**. 설치 전 `pip install --dry-run`으로 확인하세요(`numpy` 1.26.4 유지, CLAUDE.md 참고).

**연습 순서 제안**
1. 위 손계산 3개를 종이로 풀고 코드 결과와 비교.
2. 5강 정답 5개 vs 7강 노트북에서 `model.transcribe`한 결과로 WER/CER 구하기(7강 노트북 3번 셀의 경로만 바꿔 반복).
3. **내 목소리로 같은 문장 3~5개**를 녹음해 같은 방법으로 비교(WER이 어떻게 달라지는지 기록 — 프로젝트의 "비교 실험" 재료).
4. 정규화 규칙(구두점·띄어쓰기·숫자 표기)을 바꿔 보며 점수가 어떻게 달라지는지 기록.

### 7.4 TTS 구조(음향 모델·보코더) 한눈에 — **[일반 지식] 개념 정리, 수업에서 확인하지 않음**
```text
텍스트  →  ①텍스트 전처리  →  ②음향 모델(acoustic model)  →  ③보코더(vocoder)  →  음성 파형
"안녕"     (숫자·약어 읽기,     글자/발음 → Mel 스펙트로그램         Mel → 실제 소리(파형)
            발음 기호 변환)      (시간에 따른 소리 모양을 예측)
```
| 단계 | 하는 일 | 수업과의 연결 |
|---|---|---|
| ① 텍스트 전처리 | 숫자·약어를 읽는 글자로 바꾸고, 글자를 발음 단위로 바꿈 | 5강의 토큰화와 비슷한 "글 → 번호/단위" 단계 |
| ② **음향 모델** | 텍스트(발음)를 받아 **Mel 스펙트로그램**(시간별 주파수 모양)을 예측 | **4강의 Mel/Log-Mel이 이 단계의 출력** |
| ③ **보코더** | **Mel 스펙트로그램을 실제 파형(소리)으로 복원** | **STFT·Mel의 반대 방향**(3~4강에서 소리→Mel을 했다면 이것은 Mel→소리) |
- **STT와 TTS는 서로 반대 방향**입니다: STT = 소리 → Mel → 텍스트, TTS = 텍스트 → Mel → 소리. 그래서 **Mel이 두 쪽의 공통 중간 표현**입니다.
- 이 세 단계를 **하나의 모델로 합친 "종단간(end-to-end)" 모델**도 있습니다.
- 대표적인 이름(검색 키워드로 활용): 음향 모델 **Tacotron 2, FastSpeech 2**, 보코더 **WaveNet, HiFi-GAN**, 종단간 **VITS** **[기억에 의존한 일반 지식, 발표에 쓰기 전에 논문·공식 문서로 확인 필요]**.
- **OpenAI TTS API의 내부 구조는 공개된 정보를 확인하지 못했습니다 [미확인]**. 프로젝트에서는 **API를 호출하는 블랙박스**로 쓰며, 위 구조는 "TTS가 일반적으로 이렇게 구성된다"는 개념 설명용입니다.

### 7.5 이 아이디어(노래로 외국어 학습)와의 연결
| 프로젝트 부분 | 필요한 지식 | 수업에서 | 보완 |
|---|---|---|---|
| TTS로 문장 들려주기 | API 호출 방법 | `013_openai_api` **[확인]** | 구조(7.4)는 개념만 |
| 받아쓰기·읽기 채점 | **WER/CER** | **없음** | **7.3으로 자습(필수)** |
| 내 녹음 → STT | Whisper 사용법 | 7강, `013` **[확인]** | 정규화 규칙 정하기 |
| TTS 음성 vs 내 녹음 비교 실험 | Mel·파형 시각화 | 3~4강 **[확인]** | 이미 가능 |
- **"STT가 맞게 인식했다 = 발음이 정확하다"가 아님**을 계속 주의합니다(4.3절). Whisper가 문맥으로 **틀린 발음도 올바른 문장으로 고쳐 적을** 수 있어서, WER/CER은 **"단어 일치도"** 이지 **발음 평가가 아닙니다 [일반 지식 + 4.3절]**.

> 아래는 **초안**입니다. 강사님 양식·분량은 모르고, 숫자는 **제 제안값 [추정]** 이라 본인 상황에 맞게 조정하세요. LLM 서비스를 사용해 작성하는 것이 허용된다고 하니, 8.5의 요청문을 활용할 수 있습니다. LLM이 쓴 숫자·사실은 **반드시 직접 확인**하세요(이 문서의 이전 LLM 답변들에서도 확인되지 않은 주장이 있었습니다, 3.3절).

**1. 프로젝트 개요**
- **목적**: 외국어(또는 한국어) 문장을 **듣고 받아쓰기**하고 **따라 읽은 녹음을 음성 인식으로 확인**해, **정답 문장과의 일치도(WER/CER)** 와 **틀린 부분**을 보여 주는 연습 도구를 만든다. (발음 점수가 아니라 **문장 인식 일치도**임을 명시)
- **범위(포함)**: 연습 문장 10개(직접 작성), TTS로 문장 재생, 받아쓰기 입력 채점, 녹음 → STT → 정답 비교, 틀린 단어·글자 표시, 연습 기록 저장, 조건 비교 실험 1개.
- **범위(제외)**: 노래·가사 자동 처리, 발음·억양·음정 평가, 실시간 스트리밍, 다수 사용자 계정, 모델 추가 학습.
- **성공 기준(SMART, 측정 가능)** — **L1/L2/L3 구분은 해석이 불확실해 "필수·확장·도전"으로 임시 표기** [추정]
  | 단계 | 목표 | 측정 방법 |
  |---|---|---|
  | **L1 필수** | 연습 문장 10개에 대해 **녹음 업로드 → STT → WER·CER 표시**가 오류 없이 동작 | 문장 10개 × 3회 실행, 실패 0회, 정규화 규칙을 문서에 명시 |
  | **L2 확장** | **TTS 받아쓰기 흐름** + **틀린 부분 하이라이트** + **연습 기록 저장·일치율 그래프** | 기능 3개 시연, 기록 CSV 30행 이상 |
  | **L3 도전** | **조건 비교 실험**(예: 조용한 환경 vs 잡음, 모델 크기 tiny vs base 중 1개)의 WER/CER 표와 해석 | 조건당 문장 10개, 결과 표 + 그래프 1개 |
- 기한: **프로젝트 종료일 전까지(정확한 날짜 확인 필요)**.

**2. 기술 스택** — Python, `faster-whisper`(7강, 로컬 STT) 또는 OpenAI STT(013), OpenAI TTS(013), NumPy·SciPy·matplotlib(017), Pandas(CSV 기록), `difflib`(틀린 부분 표시, 파이썬 표준 라이브러리), (선택) 화면 도구는 **수업에서 쓰지 않았으므로 필요 여부를 질문 후 결정**(`ipywidgets` 또는 Streamlit 등 **[미확인]**).

**3. 프로그램 구조(강조 항목)**
```text
[연습 문장 목록(CSV)]
        ├─ 듣기 연습: TTS로 재생 → 사용자 받아쓰기(텍스트 입력) ─┐
        └─ 읽기 연습: 마이크/파일 녹음 → 16kHz 모노 변환 → STT ───┤
                                                                   ▼
                                       정규화(구두점·공백) → WER/CER 계산 → 틀린 부분 표시
                                                                   ▼
                                               연습 기록(CSV) 저장 → 일치율 그래프, 실험 표
```
- 구성 요소별 파일(예): `sentences.csv`, `tts.py`, `stt.py`, `scoring.py`(WER/CER), `app` 화면 코드, `results/`(기록·그래프).

**4. Data 수집 방법(강조 항목)**
- **연습 문장**: **직접 작성한 예문** 10개(저작권 문제 없음). 상업 가사·음원은 사용하지 않음.
- **음성**: ① **내가 직접 읽은 녹음**(개인 음성은 공개 저장소에 올리지 않음, 이 저장소의 `.gitignore` 규칙 유지), ② **TTS로 생성한 음성**(OpenAI API 약관·사용 한도는 **확인 필요**), ③ 수업 제공 WAV 5개(기능 확인용, 사용 범위 확인).
- 정답은 **내가 쓴 문장 그대로**이므로 별도 라벨링이 필요 없음.

**5. 도출 결과물**
- 동작하는 연습 도구(시연), **WER/CER 계산 코드와 정규화 규칙 문서**, **조건 비교 실험 결과(표·그래프)**, **README(사용법·한계)**, 발표 자료. 한계: "발음 정확도 평가가 아님, 인식 모델 오류가 결과에 영향".

**6. 일정 관리 (36시간 = 9일 × 4시간 가정, [추정])**
| 일차 | 할 일 |
|---|---|
| 1 | 환경 점검(마이크 녹음, Whisper 로컬 로드·OpenAI TTS/STT 호출 테스트·키 한도 확인), 연습 문장 10개 확정, **Notion 페이지 개설**, WER/CER 함수 이식 |


- 깊이는 세 곳에서 만들 수 있고 **계획서에 반영**했습니다.
  1. **평가 설계**: 정규화 규칙·언어별 단위(WER/CER)에 따른 점수 변화(이미 같은 5개 WAV에서 0.060 대 0.200으로 확인한 현상)를 **체계적으로 비교**.
  2. **실험**: 조용한 환경 vs 잡음, 모델 크기, **"노래에서 텍스트 추출"이 실제로 어려운지 데이터로 검증(L3-a)**, **STT 신뢰 지표와 실제 오류의 관계(L3-b)**.
  3. **직접 학습 컴포넌트(L3-c)**: **녹음 품질 분류기**를 Log-Mel + 소형 DNN/CNN으로 학습해 STT 전에 경고하는 기능으로 연결 → B안의 "직접 학습" 경험을 **내 주제 안에서** 얻습니다.
- 평가 기준을 강사님이 알려 주지 않았으므로(미확인) **완성도(L1~L2)와 깊이(L3)의 비중**은 면담에서 확인하는 것이 좋습니다.
