## 1. 프로젝트 개요

### 목적

- **무엇을 달성하고자 하는가?**
  - **한국어 학습자**가 외국어(영어·일본어·프랑스어 등) 노래에서 떠올린 **직접 작성한 연습 문장**을 **TTS 기준 음성(선택한 TTS 음성의 발화)으로 듣고**, **따라 읽은 녹음을 음성 인식(STT)으로 확인**해 **정답 문장과의 오류율(WER/CER)** 과 **틀린 부분**을 피드백받는 연습 도구를 만든다.
  - **제품 정의**: 노래는 **학습 동기**이고, 이번 결과물은 **직접 작성한 문장 기반의 Jupyter 노트북 프로토타입**입니다(노래 가사·음원 처리, 웹/PWA 앱은 범위 밖이며 후속 확장). 발표·README에서도 "노래 가사를 사용했다"가 아니라 "노래에서 영감을 얻어 직접 쓴 문장"으로 표현합니다.
- **배경**: 좋아하는 외국어 노래의 뜻을 알고 정확한 발음으로 따라 부르고 싶지만, 내 발음이 맞는지 확인하기 어렵습니다. 사전학습 STT·TTS를 이용하면 **듣기 → 따라 읽기 → 확인**의 연습 순환을 자동화할 수 있고, **LLM 서비스 API를 호출하여 연습 문장의 뜻, 연관 단어 및 표현**도 함께 학습할 수 있습니다.
- **중요한 한계(명시)**: STT는 문맥으로 **틀린 발음도 올바른 문장으로 고쳐 적을 수** 있습니다. 이 도구의 점수는 **발음 정확도가 아니라 "문장 인식 일치도"** 입니다.
- **추가 한계(명시)**: 모든 녹음은 **본인 한 명**의 목소리라서 **다른 화자·기기에서도 같다고 주장하지 않습니다**. 잡음 실험은 **합성 흰 잡음과 소수 문장**에 한정됩니다.
- **목표(SMART)** — *specific + measurable + achievable + relevant + time-bound*
  - **Specific**: 연습 문장의 TTS 듣기 → 녹음 → STT → 정규화 → WER/CER → 틀린 부분 표시까지의 **한 가지 연습 흐름**을 완성한다.
  - **Measurable**: 문장 10개 × 3회 = **30건**을 오류 없이 처리하고 채점 결과를 손계산 5건과 대조한다(성공 기준 참고).
  - **Achievable**: 필수 데이터(문장·녹음)를 **직접 만들 수 있고**, STT·TTS는 **사전학습 모델/API를 사용**하며(7강·013), 단계(L1→L2→L3)로 나누어 위험을 줄인다.
  - **Relevant**: 7강(Whisper)·013(STT/TTS)·1~4강(음성 전처리)을 활용하고, 수업에서 다루지 않은 **WER/CER 평가를 자습으로 보완**해 연결한다. 또한 Whisper가 내부에서 만드는 **Log-Mel `(80, 프레임)`** 과 4강에서 만든 **`(40, 프레임)`** 을 비교해 **수업 개념과 모델 내부를 연결**한다.
  - **Time-bound**: **2026-11-11(수)까지 개발**하고 **11-12(목) 발표**한다(L1 11-04, L2 11-06, L3 11-10 완료 목표).

### 프로젝트 방향 (복습·활용 중심)

- **방향**: 이 프로젝트는 **지난 6주 수업 내용을 복습하고 활용하는 수단**으로 진행합니다. 실제로 개발하는 9일 동안 **새로운 기능·기술 시도는 최소화**합니다.
- **복습 범위**: **음성 과정 1~7강과 013(OpenAI API)** 중심입니다. 014~016(LangChain·LangGraph·RAG), CNN·RNN 등은 이번 프로젝트의 복습 범위가 아닙니다.
- **새 시도의 한도 규칙**
  1. **필수로 새로 배우는 것은 WER/CER과 편집 거리 역추적 두 가지뿐**입니다(수업에서 다루지 않은 부분의 자습이며, WER/CER 계산 코드는 구현·검증 완료, 틀린 부분 표시를 위한 **역추적은 `scoring.py`에서 추가**하고 `difflib`은 보조로만 씁니다).
  2. **새 라이브러리 설치는 3일차(11-03)까지**만 하고, 이후에는 설치하지 않습니다.
  3. **웹 화면(Streamlit 등), 잡음 제거 모듈, 시간 신축(Phase Vocoder) 같은 새 DSP 실험** 등 **새 도구는 기본 범위에서 제외**하고 확장·선택으로만 둡니다. L2의 **HTML 재생 제어**는 한 번 동작을 확인한 뒤 안 되면 기본 플레이어로 대체합니다.
  4. **일정이 밀리면 새 시도 항목부터 제외**합니다(6장 축소 규칙).

### 범위

- **포함될 사항**

  | 단계          | 내용                                                                                                                                                 |
  | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
  | **L1 (필수)** | **한 언어**(영어 **[가정]**)의 연습 문장 10개, **읽기 연습**: TTS 듣기 → 녹음 입력 → **녹음 입력 상태 점검(빈 파일·너무 작음·대부분 무음·클리핑 경고. 잡음 판별은 아님)** → STT(**기본 faster-whisper tiny**) → 정규화 → WER/CER(오류율) → 틀린 부분 표시 |
  | **L2 (확장)** | **언어 1개 추가**(일본어 우선 **[가정]**, TTS·STT 확인 후. 2번째 언어는 여유 시), 언어별 정규화 규칙, **받아쓰기 모드**(TTS를 듣고 입력한 텍스트를 같은 채점으로 비교, 재생 속도·±5초는 HTML 플레이어로 시도), **연습 기록 저장·오류율 그래프**, **LLM으로 문장의 뜻·연관 단어·표현 제공**(직접 검수) |
  | **L3 (심화)** | 아래 중 **1~2개 선택**: **(a) 노래 구간 인식 실험**(말 vs 노래), **(b) STT 신뢰 지표와 실제 오류의 관계 분석**, **(c) 직접 학습한 녹음 품질 분류기**, **(d) 잡음 견고성 실험**(합성 잡음 SNR별 인식 오류 변화, 실험 조건에 한정) |

  - **개발 방식: L1을 먼저 개발하고, 시간이 남으면 L2, L3를 추가합니다.**

- **제외될 사항**
  - **상업 노래의 가사·음원 사용**(저작권, 공개 저장소) — 연습 문장은 **직접 작성한 예문**과 **사용 가능이 확인된 공개 문장**으로 한정
  - **LLM에 상업 가사 전문을 입력·저장하는 것**(뜻·표현 설명은 **직접 쓴 연습 문장**에만 적용)
  - **발음·억양·음정·박자 평가**(전문 발음 평가는 범위 밖)
  - 노래 소리로 곡 검색, 가수 목소리 분리, 가사 자동 추출을 **서비스 기능으로 완성**하는 것(L3-a는 **실험**이며 기능이 아님)
  - 다수 사용자 계정·서버 배포, 실시간 스트리밍 인식, 사전학습 모델의 **추가 학습(fine-tuning)**
  - **녹음 하나에서 SNR을 자동 추정하거나 잡음 여부를 판별하는 기능**(입력 상태 점검은 음량·무음·클리핑만 다룸), **리샘플링·시간 신축 비교 같은 새 DSP 실험**, **다른 화자 일반화 주장**

## 3. 프로그램 구조

### 데이터 흐름
```text
[연습 문장 목록 sentences.csv]  (id, 언어, 문장, 한국어 뜻, 출처, 라이선스)
        │
        ├─① 듣기: 문장 → TTS(OpenAI) → 기준 음성 재생 (생성 음성은 캐시, L2: 재생 속도·±5초)
        │
        ├─② 학습 보조 (L2): 문장 → LLM(OpenAI 채팅 모델) → 뜻·연관 단어·표현 → 직접 검수 후 표시·저장
        ├─②' 받아쓰기 (L2): TTS 듣기 → 입력 텍스트 → 같은 정규화·WER/CER → 틀린 부분 표시 (STT 없음)
        │
        └─③ 말하기: 사용자 녹음(wav/m4a) → 16kHz 모노 → 녹음 입력 상태 점검(경고) → STT(faster-whisper 또는 OpenAI)
                                                          │ 인식 문장
                                                          ▼
         정답 문장 ──────────────▶ 정규화(언어별 규칙) ─▶ WER·CER 계산 ─▶ 틀린 부분 표시(difflib)
                                                          │
                                                          ▼
                                    연습 기록(CSV) 저장 ─▶ 오류율 그래프 (L2)
```

### 언어별 정규화 규칙 (설계 포인트)
| 언어           | 단위                    | 규칙(초안)                       | 주의                                                   |
| -------------- | ----------------------- | -------------------------------- | ------------------------------------------------------ |
| 영어           | WER 중심, CER 보조      | 소문자화, 구두점 제거, 공백 정리 | 축약형(don't), 숫자 표기                               |
| 한국어(검증용) | WER·CER                 | 구두점·공백 정리                 | 조사 때문에 WER이 CER보다 가혹                         |
| 일본어         | **CER 중심**(공백 없음) | 구두점 제거                      | 한자·히라가나·가타카나 표기 차이는 오류로 세어짐(한계) |
| 프랑스어       | WER·CER                 | 소문자화, 구두점 제거            | 악센트(é, è) 처리 방침 결정 필요                       |

**영어 정규화 확정 항목 (1일차에 코드로 고정)**
- 유니코드 NFC 정규화 → 소문자화 → 구두점 제거 → 연속 공백 정리
- 축약형(`don't` 등)·숫자 표기: 규칙을 하나로 고정하거나 **연습 문장에서 쓰지 않도록** 작성 **[1일차 결정]**
- **정답이 빈 문자열이면 계산하지 않고 오류로 처리**(분모 0)
- **WER은 1을 넘을 수 있으므로**(삽입이 많을 때, 예: 정답 1단어 vs 인식 3단어 → 2.0) 화면에는 `1−WER` 같은 "일치율"이 아니라 **오류율(WER·CER)과 치환·삭제·삽입 개수**로 표시

### L3 선택 메뉴 (L1·L2 완료 후 남은 시간 기준)
| 안                                 | 내용                                                                                                                                 | 필요 데이터                | 예상 시간 | 깊이를 주는 점                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- | --------- | -------------------------------------------------------------------------- |
| **(a) 노래 구간 인식 실험**        | **직접 부른 짧은 구간**(또는 퍼블릭 도메인 곡)을 같은 문장의 **낭독과 비교**해 CER 차이를 측정(**선택, 여유 시**: 말·노래의 스펙트로그램 비교로 음의 길이·배음 차이 설명)                                       | 문장 5~10개 × (낭독, 노래) | 약 6h(+1h)| "노래에서 텍스트 추출"이라는 원래 구상이 실제로 어려운지 **데이터로 확인** |
| **(b) STT 신뢰 지표 vs 실제 오류** | `faster-whisper`가 주는 `avg_logprob`, `no_speech_prob`, 언어 확률과 **실제 CER의 관계** 분석 → 신뢰도가 낮으면 **"다시 녹음" 안내** | L1·L2에서 쌓은 기록        | 약 5h     | 지표가 실제로 쓸모 있는지를 **통계로 검증**                                |
| **(c) 녹음 품질 분류기 직접 학습** | 정상/잡음/무음·작음 녹음을 **Log-Mel로 변환해 소형 DNN/CNN을 학습**, 새 녹음의 품질을 판별해 **STT 전에 경고**(**선택, 여유 시**: 입력 특징을 4강의 40 Mel과 Whisper의 80 Mel로 비교)                       | 클래스당 30~40개 녹음      | 약 10h(+1~2h) | 수업(4~6강)의 **"직접 학습"을 서비스 기능으로 연결**                       |
| **(d) 잡음 견고성 실험** | **같은 녹음에 SNR 0/5/10/20 dB 잡음을 섞어(시드 3개)** WER/CER 곡선을 그리고 **오류가 급증하는 SNR 구간**을 관찰(일반 임계값이 아님). 사용자 녹음 하나의 SNR 추정은 **별도 문제**라 한계로 기록. **깨끗한 원본·10 dB·0 dB의 스펙트로그램 그림**으로 잡음이 퍼지는 주파수 대역을 설명. 확장: **강사님이 언급한 잡음 제거 모듈의 전/후 비교**, 실제 잡음(카페·거리) 녹음 | L1·L2의 깨끗한 녹음 + 합성 잡음(확장 시 실제 잡음 녹음) | 최소 약 5h(스펙트로그램 포함) ~ 확장 약 8h | **점수가 잡음 때문에 떨어진 것을 발음 오해로 받아들이지 않게 하는 설계 근거**를 만듦 |

- **L3-c와 (d)는 둘 다 하지 않습니다.** 강사님이 직접 학습 모델을 중요하게 본다고 확인되면 (d) **대신** (c)를 선택합니다(확정 안 된 항목 9).
- **권장 조합**: **기본은 (d)(최소 구성 + 스펙트로그램, 약 5h)** 입니다. 7·8일차(8h)에 테스트·README까지 들어가므로, **일정이 앞당겨진 경우에만 (b) 또는 (a)·(c) 중 하나**를 추가합니다.

- **일정을 지키기 위한 현실적인 계획**
  - **지연 시 축소 규칙**: **새 시도 항목부터 제외**합니다. L2에서 일정이 밀리면 **① LLM 뜻·표현 → ② 재생 속도·±5초 → ③ 받아쓰기 모드 → ④ 기록·그래프 → ⑤ 추가 언어** 순으로 뺍니다(L1이 4일차까지 끝나지 않으면 L2는 **언어 추가만** 합니다). L2가 6일차까지 끝나지 않으면 L3는 **(d)의 최소 구성(SNR별 곡선)만** 합니다. **L3는 항상 선택**입니다.
  - **Notion 기록은 매일 10~30분**(간단한 날 10분, 실험한 날 30분, 합계 약 2h)이고, 8일차에 **예비 시간 약 2h**를 둡니다. 따라서 **순수 구현 시간은 약 32h**로 계산합니다.
  - **강사님 면담(하루 1~3회) 활용**: 1일차(범위·환경 확인), 4일차(L1 시연과 L2/L3 선택 상담), 8일차(실험 결과 해석).

## 8. 평가·검증 계획

| 검증 대상        | 방법                                                                    | 기준              |
| ---------------- | ----------------------------------------------------------------------- | ----------------- |
| 채점 코드 정확성 | **손계산 5건**과 코드 결과 비교, 경계 사례(빈 정답·동일 문장·삽입이 많아 WER>1), 역추적한 치환·삭제·삽입 합 = 편집 거리 | 전부 일치         |
| L1 안정성        | 문장 10개 × 3회 처리                                                    | 실패 0건          |
| 정규화의 영향    | 같은 녹음에 **규칙 A/B/C**로 채점해 비교                                | 규칙별 WER·CER 표 |
| 언어별 차이(L2)  | 언어별 문장 10개의 평균 WER·CER                                         | 표 + 해석         |
| LLM 뜻·표현(L2) | 문장 10개의 설명을 **직접 검수**(뜻 정확성·표현 적절성) | 오류 건수·유형 표 |
| 환경·모델 차이   | 조용한 환경 vs 잡음 환경, tiny vs base 중 **1개**                       | 표 + 해석         |
| 잡음 견고성(L3-d) | SNR 0/5/10/20 dB와 깨끗한 원본 × **시드 3개** 반복, 합산 WER·CER의 평균·범위, 합성 후 **실제 SNR을 다시 계산해 검증** | 곡선 그림 + 조건 한정 해석 |
| 스펙트로그램 그림(L3) | 비교하는 그림은 **같은 STFT·Mel 설정과 같은 색 범위**로 생성, 설정값을 그림 옆에 기록 | 설정 기록 + 한 줄 해석 |
| (L3) 선택 실험   | 5장 메뉴 참고                                                           | 표·그래프·해석    |

- **평가 데이터는 학습·튜닝에 쓰지 않습니다.** (L3-c는 녹음 세션 단위로 분리)
- **무작위 요소가 있는 실험(잡음 합성 등)은 시드를 바꿔 3회 이상 반복하고 평균·범위를 보고합니다.** (같은 SNR에서도 시드에 따라 WER이 0.04~0.06 달라진 예가 있었음)
