# 프로젝트 개발 계획서_20261030

**프로젝트:** 외국어 노래 문장 연습 도우미 — 듣고 따라읽고 받아쓰고 확인하는 음성 학습 프로토타입

**작성일:** 2026-10-29(목) · **프로젝트 기간:** 2026-10-30(금) ~ 11-11(수) 평일 9일 × 하루 4시간 = 36시간 개발 → **11-12(목) 발표**

## 1. 프로젝트 개요

### 목적(무엇을 달성하고자 하는가?)
- **한국어 사용자**가 외국어(영어·일본어·프랑스어 등) 노래에 나오는 문장을 프로그램에 직접 입력하면
- **TTS 기준 음성(선택한 TTS 음성의 발화)으로 듣고**, 
- **따라읽은 녹음을 음성 인식(STT)으로 확인**하거나 **받아쓰기**를 하고
- **정답 문장과의 오류율(WER/CER)** 과 **틀린 부분**을 피드백받는 연습 도구를 만듭니다.
- **LLM 서비스 API를 호출하여 연습 문장의 뜻, 연관 단어 및 표현**도 함께 학습할 수 있습니다.
 
### 목표
- **Specific**: 연습 문장의 TTS 듣기 → 녹음 → STT → 정규화 → WER/CER → 틀린 부분 표시까지의 **한 가지 연습 흐름**을 완성
- **Measurable**: 문장 10개 × 3회 = **30건**을 오류 없이 처리하고 채점 결과를 손계산 5건과 대조
- **Achievable**: 필수 데이터(문장·녹음)를 **직접 만들 수 있고**, STT·TTS는 **사전학습 모델/API를 사용**하며, 구현 단계(L1→L2→L3)로 나누어 위험을 줄임
- **Relevant**: 수업에서 다룬 Whisper(활용, Whisper가 내부에서 만드는 **Log-Mel `(80, 프레임)`** 살펴보기 등), STT/TTS, 음성 전처리를 활용하고, 수업에서 다루지 않은 **WER/CER 평가를 자습으로 보완**해 연결
- **Time-bound**: **2026-11-11(수)까지 개발**(`L1` 11-04, `L2` 11-06, `L3` 11-10 완료 목표)

### 범위(포함될 사항)

  | 단계          | 내용                                                                                                                                                                                                                                                                                                                                                           |
  | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | **L1 (필수)** | 영어 노래 문장 10개, **읽기 연습**: TTS 듣기 → 녹음 입력 → **녹음 입력 상태 점검(빈 파일·너무 작음·대부분 무음·클리핑 경고. 잡음 판별은 아님)** → STT(**기본 faster-whisper tiny**) → 정규화 → WER/CER(오류율) → 틀린 부분 표시                                                                                                                                |
  | **L2 (확장)** | **받아쓰기 모드**(TTS를 듣고 입력한 텍스트를 같은 채점으로 비교), **재생 제어**(속도 0.75~1.25×·±5초·일시정지, HTML 플레이어로 시도), **연습 기록 저장·오류율 그래프**, **LLM으로 문장의 뜻·연관 단어·표현 제공**(직접 검수)                                                                                                                                   |
  | **L3 (심화)** | 아래 중 **1~2개 선택**: (a) **언어 1개 추가**(일본어 우선, TTS·STT 확인 후. 2번째 언어는 여유 시), 언어별 정규화 규칙, **(b) 노래 구간(말 vs 노래) 또는 노래 주파수(음악 vs 음성) 인식 실험**, **(c) STT 신뢰 지표와 실제 오류의 관계 분석**, **(d) 직접 학습한 녹음 품질 분류기**, **(e) 잡음 견고성 실험**(합성 잡음 SNR별 인식 오류 변화, 실험 조건에 한정) |

## 3. 프로그램 구조

### 데이터 흐름
```text
[연습 문장 목록 sentences.csv]  (id, 언어, 문장, 한국어 뜻, 출처, 라이선스)
        │
        ├─① 듣기: 문장 → TTS(OpenAI) → 기준 음성 재생 (생성 음성은 캐시, `L2` HTML 플레이어로 속도·±5초·일시정지)
        │
        ├─② (a) 받아쓰기 (`L2`): 기준 음성 듣기(재생 제어) → 입력 텍스트 → 같은 정규화·WER/CER → 틀린 부분 표시
        ├─② (b) 학습 보조 (`L2`): 문장 → LLM(OpenAI 채팅 모델) → 뜻·연관 단어·표현 → 직접 검수 후 표시·저장
        │
        └─③ 말하기: 사용자 녹음(wav/m4a) → 16kHz 모노 → 녹음 입력 상태 점검(경고) → STT(faster-whisper 또는 OpenAI)
                                                          │ 인식 문장

                                                          │
                                                          ▼
                                    연습 기록(CSV) 저장 ─▶ 오류율 그래프 (L2)
```

### 언어별 정규화 규칙
| 언어           | 단위                    | 규칙(초안)                       | 주의                                                   |
| -------------- | ----------------------- | -------------------------------- | ------------------------------------------------------ |
| 영어           | WER 중심, CER 보조      | 소문자화, 구두점 제거, 공백 정리 | 축약형(don't), 숫자 표기                               |
| 한국어(검증용) | WER·CER                 | 구두점·공백 정리                 | 조사 때문에 WER이 CER보다 가혹                         |
| 일본어         | **CER 중심**(공백 없음) | 구두점 제거                      | 한자·히라가나·가타카나 표기 차이는 오류로 세어짐(한계) |
| 프랑스어       | WER·CER                 | 소문자화, 구두점 제거            | 악센트(é, è) 처리 방침 결정 필요                       |

#### 영어 정규화 항목 (1일차에 코드로 고정)
- 유니코드 NFC 정규화 → 소문자화 → 구두점 제거 → 연속 공백 정리
- 축약형(`don't` 등)·숫자 표기: 규칙을 하나로 고정하거나 **연습 문장에서 쓰지 않도록** 작성 **[1일차 결정]**
- **정답이 빈 문자열이면 계산하지 않고 오류로 처리**(분모 0)
- **WER은 1을 넘을 수 있으므로**(삽입이 많을 때, 예: 정답 1단어 vs 인식 3단어 → 2.0) 화면에는 `1−WER` 같은 "일치율"이 아니라 **오류율(WER·CER)과 치환·삭제·삽입 개수**로 표시
  
### 받아쓰기 모드와 재생 제어 (`L2`)
- **받아쓰기 흐름**: 문장 선택 → 기준 음성(캐시된 wav) 듣기 → 들은 내용을 입력(`input()`) → 정답과 **같은 `scoring.py`** 로 채점 → 오류율과 틀린 부분 표시 → 기록 CSV 저장. STT를 쓰지 않으므로 읽기 연습(L1)과 달리 **입력 텍스트가 곧 인식 결과**입니다.
- **재생 제어 구현**: wav는 **한 번만 생성해 캐시**하고, 노트북 셀에서 `IPython.display.HTML`로 `<audio>`와 버튼(처음부터 · −5초 · 재생/일시정지 · +5초 · 속도 0.75/0.9/1.0/1.1/1.25×)을 출력합니다. 브라우저 오디오의 `playbackRate`(속도), `currentTime`(위치 이동), `pause()`/`play()`를 쓰므로 **속도를 바꿔도 TTS API를 다시 호출하지 않고 원본 wav도 바뀌지 않습니다.**
- **동작 확인(5일차 시작 전 10분)**:VS Code에서 위 플레이어가 동작하는지 먼저 확인합니다 **[확인 필요]**. 동작하지 않으면 **기본 `IPython.display.Audio` 플레이어**(재생·일시정지·탐색 바만 제공)로 대체하고 그 사실을 기록합니다.
- **체크리스트(5항목)**: ① 속도별 재생 시간이 달라진다(0.75×면 약 1.33배) ② ±5초 이동이 된다 ③ 일시정지 후 위치가 유지된다 ④ 속도를 바꿔도 원본 wav가 그대로다 ⑤ Jupyter·VS Code 중 사용할 환경에서 동작한다.
- **범위 밖**: 피치를 유지하며 속도를 바꾸는 신호처리(Phase Vocoder)와 리샘플링 비교는 하지 않습니다(브라우저 재생 기능만 사용).

| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------ |

- **(d) 분류기와 (e) 잡음 실험은 둘 다 하지 않습니다.** 강사님이 직접 학습 모델을 중요하게 본다고 확인되면 (e) **대신** (d)를 선택합니다(1:1 면담에서 확인).
- **권장 조합**: **기본은 (e)(최소 구성 + 스펙트로그램, 약 5h)** 입니다. 7·8일차(8h)에 테스트·README까지 들어가므로, **일정이 앞당겨진 경우에만 (a) 언어 추가 또는 (c)·(b)·(d) 중 하나**를 추가합니다.

| 저작권                                                               | 저장소·발표 문제                        | **직접 작성 문장·공개 문장만**, 상업 가사 미사용                                                                                                           |
| 개인 음성·키 노출                                                    | 보안                                    | `.env`·`data/`·`results/` 비공개, 개별 파일만 커밋                                                                                                         |
| 범위 초과·일정 지연                                                  | 미완성                                  | L1/L2/L3 단계, **축소 규칙**(6장)                                                                                                                          |
| 환경 문제(라이브러리 없음)                                           | 시간 손실                               | 설치 전 `pip install --dry-run`, numpy 1.26.4 유지                                                                                                         |

### 프로젝트 범위 상 제외될 사항
- **상업 노래의 가사·음원 사용**(저작권, 공개 저장소)
  - 연습 문장은 **직접 작성한 예문**과 **사용 가능이 확인된 공개 문장**으로 한정
- **발음·억양·음정·박자 평가**
  - 전문 발음 평가는 범위 밖
  - STT는 문맥으로 **틀린 발음도 올바른 문장으로 고쳐 적을 수** 있는 바, 이 도구의 점수는 **발음 정확도가 아니라 "문장 인식 일치도"**
- 가수 목소리 분리, 가사 자동 추출을 **서비스 기능으로 완성**하는 것
  - L3-(b)는 **실험**이며 기능이 아님
- 다수 사용자 계정·서버 배포
- 노래 소리로 곡 검색, 실시간 스트리밍 인식
- 사전학습 모델의 **추가 학습(fine-tuning)**
- **녹음 하나에서 SNR을 자동 추정하거나 잡음 여부를 판별하는 기능**
  - 입력 상태 점검은 음량·무음·클리핑만 다룸
  - 잡음 실험은 **합성 white noises와 소수 문장**에 한정
- **리샘플링·시간 신축 비교 같은 새 DSP 실험**
- **다른 화자 일반화 주장** 
  - 모든 녹음은 **본인 한 명**의 목소리로써, **다른 화자·기기에서도 같다고 주장하지 않음**

## 8. 평가·검증 계획

| 검증 대상             | 방법                                                                                                                    | 기준                       |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 채점 코드 정확성      | **손계산 5건**과 코드 결과 비교, 경계 사례(빈 정답·동일 문장·삽입이 많아 WER>1), 역추적한 치환·삭제·삽입 합 = 편집 거리 | 전부 일치                  |
| L1 안정성             | 문장 10개 × 3회 처리                                                                                                    | 실패 0건                   |
| 정규화의 영향         | 같은 녹음에 **규칙 A/B/C**로 채점해 비교                                                                                | 규칙별 WER·CER 표          |
| 언어별 차이(L3-a)     | 언어별 문장 10개의 평균 WER·CER                                                                                         | 표 + 해석                  |
| LLM 뜻·표현(L2)       | 문장 10개의 설명을 **직접 검수**(뜻 정확성·표현 적절성)                                                                 | 오류 건수·유형 표          |
| 환경·모델 차이        | 조용한 환경 vs 잡음 환경, tiny vs base 중 **1개**                                                                       | 표 + 해석                  |
| 잡음 견고성(L3-e)     | SNR 0/5/10/20 dB와 깨끗한 원본 × **시드 3개** 반복, 합산 WER·CER의 평균·범위, 합성 후 **실제 SNR을 다시 계산해 검증**   | 곡선 그림 + 조건 한정 해석 |
| 스펙트로그램 그림(L3) | 비교하는 그림은 **같은 STFT·Mel 설정과 같은 색 범위**로 생성, 설정값을 그림 옆에 기록                                   | 설정 기록 + 한 줄 해석     |
| 재생 제어(L2)         | 체크리스트 5항목(속도별 재생 시간, ±5초 이동, 일시정지 후 위치, 원본 wav 불변, 사용할 환경에서 동작)                    | 통과 또는 대체 기록        |
| (L3) 선택 실험        | 5장 메뉴 참고                                                                                                           | 표·그래프·해석             |

### 평가 원칙
- **평가 데이터는 학습·튜닝에 쓰지 않습니다.**
  - L3-(d)는 녹음 세션 단위로 분리
- **무작위 요소가 있는 실험(잡음 합성 등)은 시드를 바꿔 3회 이상 반복하고 평균·범위를 보고합니다.** 
  - 같은 SNR에서도 시드에 따라 WER이 0.04~0.06 달라진 예가 있었음
