# Transformer — Positional Encoding(위치 인코딩) 정리

> 질문: Transformer는 단어를 순차가 아니라 **병렬**로 입력받는데, 그러면 단어의 앞뒤 순서는 어떻게 아는가?
> 근거 논문: Vaswani et al., *Attention Is All You Need* (NeurIPS 2017), 같은 폴더의 `transformer.pdf` (arXiv:1706.03762).
> 논문 인용은 PDF 본문을 직접 확인한 것이고, 아래 수치 예시는 직접 계산한 값입니다. 논문 번호(§, Table)는 PDF 기준입니다.

---

## 1. 결론부터

- 이해하신 대로 맞아요. Transformer는 문장의 모든 단어를 **한꺼번에** 넣습니다.
- 그리고 **Self-Attention 연산 자체는 순서를 전혀 모릅니다.** (아래 2절에서 수식으로 보입니다.)
- 그래서 논문은 **단어 임베딩에 "위치 정보 벡터"를 더해서** 입력합니다. 이게 Positional Encoding(PE)입니다.
- 위치 정보는 "순서대로 처리"해서 얻는 게 아니라, **각 위치마다 고유한 벡터를 계산해서 값 안에 심어 넣는** 방식으로 얻습니다.

한 줄 요약: **순서를 "처리 방식"으로 표현하던 RNN → 순서를 "입력 값"으로 표현하는 Transformer.**

---

## 2. 왜 위치 정보가 따로 필요한가 (수식으로)

### 2.1 RNN은 순서를 구조로 알고 있다

논문 §1: RNN은 은닉 상태를 `h_t = f(h_{t-1}, x_t)` 로 계산하므로 "inherently sequential" 합니다. t번째 단어는 t−1번째를 처리한 **뒤에** 처리되니까, 순서가 구조 자체에 들어 있어요. 대신 병렬화가 안 되는 것이 단점이었고, Transformer는 이 순환(recurrence)을 없앴습니다.

### 2.2 Self-Attention은 순서를 구분하지 못한다

입력 행렬을 `X` (n개 단어 × d_model)라 하면, 논문 식 (1)에 따라

$$
\text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{T}}{\sqrt{d_k}}\right)V,\quad Q=XW^Q,\ K=XW^K,\ V=XW^V
$$

i번째 단어의 출력은

$$
z_i=\sum_{j=1}^{n}\alpha_{ij}\,v_j,\qquad \alpha_{ij}=\frac{\exp(q_i\cdot k_j/\sqrt{d_k})}{\sum_{m}\exp(q_i\cdot k_m/\sqrt{d_k})}
$$

여기에는 `i`, `j`가 "몇 번째인지"가 **어디에도 등장하지 않습니다.** 쓰이는 건 q_i, k_j, v_j 값뿐이에요. 따라서 단어들의 순서를 바꿔 넣으면(순열 P를 적용하면) 출력도 똑같이 순서만 바뀝니다:

$$
\text{Attention}(PX)=P\cdot\text{Attention}(X)
$$

(이 성질을 permutation equivariance라고 부릅니다.)

### 2.3 구체적인 문제 상황

두 문장을 보세요.

| | 문장 | 의미 |
|---|---|---|
| A | the **man** loves the **woman** | 남자가 여자를 사랑 |
| B | the **woman** loves the **man** | 여자가 남자를 사랑 |

PE가 없으면 두 문장은 Self-Attention에게 **같은 단어 모음(bag of words)** `{the, the, man, loves, woman}` 입니다. 'man'이 바라보는 대상(the, the, loves, woman)과 그 계산 결과가 A, B에서 똑같아서, 누가 누구를 사랑하는지 구분할 수 없어요.

(질문에서 "the man, the woman, loves 순으로 병렬 입력될 수 있지 않냐"고 하셨는데, 바로 그 점이 문제입니다. 모델 입장에서 입력 순서는 "무엇이 먼저 들어왔나"라는 정보를 담지 않아요. 행렬의 행 순서는 연산 결과에 영향을 주지 않으니까요.)

→ **순서 정보를 값 자체에 넣어줘야 한다.** 논문 §3.5 원문:

> "Since our model contains no recurrence and no convolution, in order for the model to make use of the order of the sequence, we must inject some information about the relative or absolute position of the tokens in the sequence."

## 3. 해결책: 임베딩에 위치 벡터를 "더한다"

각 위치 `pos` (0, 1, 2, …)마다 임베딩과 **같은 차원(d_model)** 의 벡터 `PE(pos)`를 만들고, 단어 임베딩에 더해서 입력으로 씁니다.

$$
x_{pos}' = \text{Embedding}(w_{pos}) + PE(pos)
$$

논문 §3.5: "The positional encodings have the same dimension d_model as the embeddings, so that the two can be summed."

이제 같은 단어라도 위치가 다르면 입력 벡터가 달라져요. 첫 번째 'the'와 네 번째 'the'가 서로 다른 벡터가 됩니다.

### 3.1 논문의 수식 (강사님 장표의 sin/cos 식)

$$
PE_{(pos,\,2i)}=\sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right),\qquad
PE_{(pos,\,2i+1)}=\cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)
$$

- `pos`: 문장 안에서 단어의 위치 (0, 1, 2, …)
- `i`: 차원 쌍의 번호 (0 ~ d_model/2 − 1). **짝수 차원(2i)은 sin, 홀수 차원(2i+1)은 cos**
- `d_model`: 임베딩 차원 (논문은 512)
- 분모 `10000^{2i/d_model}`: 차원마다 다른 "속도(주파수)"를 주는 값

기호를 풀어서 쓰면, 한 쌍(2i, 2i+1)이 쓰는 각속도를 $\omega_i = 1/10000^{2i/d_{model}}$ 라 할 때

$$
PE(pos)=\big[\sin(\omega_0\,pos),\ \cos(\omega_0\,pos),\ \sin(\omega_1\,pos),\ \cos(\omega_1\,pos),\ \dots\big]
$$

### 3.2 숫자로 직접 계산해 보기 (d_model = 4)

d_model = 4이면 쌍은 i = 0, 1 두 개이고

- $\omega_0 = 1/10000^{0} = 1$
- $\omega_1 = 1/10000^{2/4} = 1/100 = 0.01$

| pos | dim0 = sin(1·pos) | dim1 = cos(1·pos) | dim2 = sin(0.01·pos) | dim3 = cos(0.01·pos) |
|---|---|---|---|---|
| 0 | 0.0000 | 1.0000 | 0.0000 | 1.0000 |
| 1 | 0.8415 | 0.5403 | 0.0100 | 1.0000 |
| 2 | 0.9093 | −0.4161 | 0.0200 | 0.9998 |
| 3 | 0.1411 | −0.9900 | 0.0300 | 0.9996 |
| 4 | −0.7568 | −0.6536 | 0.0400 | 0.9992 |

관찰할 점:
- **각 행(위치)이 서로 다른 벡터**입니다. → 위치마다 고유한 값.
- 앞쪽 차원(dim0, dim1)은 **빨리 변하고**, 뒤쪽 차원(dim2, dim3)은 **천천히 변합니다.**

### 3.3 문장에 적용해 보기

문장 A `the man loves the woman`은 위치 0~4. 'the'가 위치 0과 3에 두 번 나옵니다.
(임베딩 값은 설명용으로 임의로 정한 가짜 값이에요. 실제로는 학습되는 값입니다.)

```
e(the) = [0.2, -0.1, 0.4, 0.0]          # 임의의 장난감 임베딩

the @ pos 0 :  e(the) + PE(0) = [0.2, -0.1, 0.4, 0.0] + [0.0000,  1.0000, 0.0000, 1.0000] = [0.2000,  0.9000, 0.4000, 1.0000]
the @ pos 3 :  e(the) + PE(3) = [0.2, -0.1, 0.4, 0.0] + [0.1411, -0.9900, 0.0300, 0.9996] = [0.3411, -1.0900, 0.4300, 0.9996]
```

같은 단어 'the'인데도 입력 벡터가 다릅니다. 같은 이유로 A와 B 문장에서 'man'은 위치(1 vs 4)가 다르니 입력 벡터도 달라요. 그래서 이후의 Self-Attention이 "man이 문장 앞쪽(주어 자리)에 있다"는 정보를 활용할 수 있게 됩니다.

### 3.4 왜 "더하기"인가? (이어 붙이지 않고)

논문은 합(sum)으로 합니다. 이어 붙이면(concat) 차원이 커지고 모든 층의 d_model이 늘어나므로, 차원을 유지하는 합이 단순합니다. 합쳐도 단어 의미와 위치 정보가 섞여 구분이 안 될까 걱정될 수 있지만, 고차원(512)에서는 모델이 학습으로 이를 분리해서 쓸 수 있다고 봅니다. (이 부분은 논문이 따로 증명하지는 않았어요 — 설계 선택에 가깝습니다.)

참고: §3.4에서 임베딩 가중치에 √d_model을 곱한다고 합니다. 임베딩 값이 PE(−1 ~ 1 범위)에 묻히지 않게 하는 규모 조정으로 이해하면 됩니다. (이 해석은 논문에 명시된 이유가 아니라 제 해석이에요.)

## 4. 왜 하필 sin / cos 인가

"위치를 고유하게 표현"만이 목적이라면 0, 1, 2, … 숫자를 그대로 넣어도 되는데 왜 삼각함수일까요?

### 4.1 후보 1: 위치 번호를 그대로 쓴다 (pos = 0, 1, 2, …)

- 값이 계속 커져서 임베딩(작은 값)을 압도하고, 학습 때 보지 못한 긴 문장에서는 처음 보는 큰 값이 됩니다.
- 위치 100과 101의 관계, 위치 3과 4의 관계를 모델이 같은 방식으로 알아보기 어려워요.

### 4.2 후보 2: 0~1로 정규화한다 (pos / 문장길이)

- 문장 길이에 따라 같은 간격(한 칸 차이)이 다른 값 차이가 됩니다. 5단어 문장의 한 칸은 0.2, 100단어 문장의 한 칸은 0.01.

### 4.3 sin/cos 방식의 장점

1. **값이 −1 ~ 1에 갇혀 있다.** 문장이 길어져도 값이 폭주하지 않습니다.
2. **여러 주파수를 겹쳐서 고유성을 확보한다.** 이진수 비유가 이해하기 좋아요.

   ```
   0 → 000
   1 → 001      맨 오른쪽 자리: 매번 0/1 바뀜 (빠르게 변함)
   2 → 010      가운데 자리  : 2칸마다 바뀜
   3 → 011      왼쪽 자리    : 4칸마다 바뀜 (느리게 변함)
   4 → 100
   ```

   PE도 비슷합니다. 앞쪽 차원은 빨리 진동하고(분모 작음), 뒤쪽 차원은 천천히 진동합니다. 이진수에서 "자리마다 바뀌는 속도가 다르다"가 위치를 고유하게 만드는 원리였죠. PE는 이를 0/1이 아니라 **연속적인 사인파**로 구현한 것입니다.
   - 논문: "The wavelengths form a geometric progression from 2π to 10000·2π." 즉 가장 빠른 차원의 파장은 2π≈6.28, 가장 느린 차원은 10000·2π≈62,832.
   - 직접 확인: d_model = 64로 위치 0~999 벡터를 만들어 보면 1000개가 **모두 서로 다른 벡터**였습니다.
3. **상대 위치를 선형 변환으로 표현할 수 있다.** (4.4절, 논문이 이 함수를 고른 핵심 이유)

### 4.4 핵심: 상대 위치가 "회전"으로 표현된다 (증명)

논문 §3.5: "We chose this function because we hypothesized it would allow the model to easily learn to attend by relative positions, since for any fixed offset k, PE_{pos+k} can be represented as a linear function of PE_pos."

쌍 하나(sin, cos)만 보고, 각속도를 ω라 합시다. 삼각함수 덧셈정리:

$$
\begin{aligned}
\sin(\omega(pos+k)) &= \sin(\omega\,pos)\cos(\omega k)+\cos(\omega\,pos)\sin(\omega k)\\
\cos(\omega(pos+k)) &= \cos(\omega\,pos)\cos(\omega k)-\sin(\omega\,pos)\sin(\omega k)
\end{aligned}
$$

행렬로 쓰면

$$
\begin{bmatrix}\sin(\omega(pos+k))\\ \cos(\omega(pos+k))\end{bmatrix}
=
\underbrace{\begin{bmatrix}\cos\omega k & \sin\omega k\\ -\sin\omega k & \cos\omega k\end{bmatrix}}_{M_k:\ \text{회전 행렬}}
\begin{bmatrix}\sin(\omega\,pos)\\ \cos(\omega\,pos)\end{bmatrix}
$$

- 행렬 $M_k$ 는 **k(거리)에만 의존하고 pos(절대 위치)에는 의존하지 않습니다.**
- 즉 "3칸 뒤"라는 관계는 어느 위치에서든 같은 회전으로 표현돼요. 그래서 모델이 "내 앞 1칸", "내 뒤 3칸" 같은 **상대적 위치 패턴**을 학습하기 쉬워진다는 가설입니다.

수치 검증(위 d_model=4 표, ω₀=1, pos=1, k=2):

```
M_2 · [sin(1), cos(1)] = [0.1411, -0.9900]  = PE(3)의 앞 두 차원  ✓
ω₁=0.01 쌍도 M_2 · [0.0100, 1.0000]  = [0.0300, 0.9996] = PE(3)의 뒤 두 차원 ✓
```

### 4.5 가까운 위치일수록 벡터가 비슷하다 (수치)

d_model = 64로 계산한 PE 벡터끼리의 내적 (pos=10 기준):

| 비교 대상 | 내적 |
|---|---|
| 자기 자신 (거리 0) | 32.00 |
| 거리 1 (pos 11) | 30.92 |
| 거리 2 | 28.30 |
| 거리 3 | 25.59 |
| 거리 4 | 23.93 |
| 거리 5 | 23.50 |
| 거리 30 (pos 40) | 17.07 |

(내적이 클수록 비슷한 벡터. 자기 자신과의 내적이 32인 이유는 sin²+cos²=1이 32쌍 있기 때문이에요.) 이 예에서는 거리가 멀어질수록 대체로 줄어드는 경향이 보입니다. 다만 사인파의 합이라 모든 거리에서 단조 감소한다는 보장은 없으니 "경향" 정도로만 이해하세요.

### 4.6 왜 10000인가?

- 논문에는 10000을 고른 이유가 따로 설명되어 있지 않습니다. 논문이 말하는 것은 "파장이 2π에서 10000·2π까지 등비수열을 이룬다"는 사실뿐이에요.
- 해석하자면: 가장 느린 파장이 약 62,832라서 수만 단어 길이까지 위치를 구분할 수 있는 여유가 있다는 정도입니다. (이건 제 해석입니다.)

## 5. 논문에서 참고할 만한 부분

PDF 본문을 읽고 정리한 것입니다.

### 5.1 §3.5 Positional Encoding (핵심)
- 위 3, 4절의 내용이 이 절의 전부입니다. 길이가 짧아요 (약 15줄). 수식 + 선택 이유 두 가지가 핵심이므로 직접 읽어 볼 만합니다.

### 5.2 학습되는 위치 임베딩과 비교 (§3.5 + Table 3 행 (E))
- 논문은 sin/cos 대신 **학습되는 위치 임베딩**(위치마다 벡터를 학습)도 실험했고 "nearly identical results"라고 씁니다.
- Table 3 행 (E): positional embedding 사용 시 개발셋 BLEU **25.7**, PPL 4.92. (기본 모델(base)과 거의 같음)
- 그럼에도 sin/cos를 고른 이유 (§3.5): "it may allow the model to extrapolate to sequence lengths longer than the ones encountered during training." → 학습 때 본 적 없는 더 긴 문장에도 적용 가능할 것이라는 기대.
- 즉 **sin/cos가 학습 방식보다 성능이 좋아서가 아니라**, 성능이 비슷하면서 파라미터가 없고 길이 확장이 가능해 보여서 선택했다는 점이 중요해요. (장표에서 "sin, cos가 최선"이라고 읽히면 이 부분이 보완됩니다.)
- 참고로 BERT 등 후속 모델은 학습되는 위치 임베딩을 쓰는 경우가 많습니다. (논문 외 내 지식이며 이 폴더의 PDF에서 확인한 사실은 아닙니다.)

### 5.3 §3.1, §3.2.3 — 디코더의 마스킹: "순서"의 또 다른 쪽
PE는 "단어가 어디에 있는가"를 알려줍니다. 한편 디코더는 **미래 단어를 보면 안 되므로** Self-Attention에서 미래 위치의 점수를 −∞로 만들어(softmax 후 0) 가립니다. 논문 §3.2.3: "masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections."
- 앞서 배운 **Teacher Forcing**과 연결됩니다. RNN 디코더는 한 글자씩 순서대로 처리했지만, Transformer는 정답 문장 전체를 한 번에 넣고 마스크로 "미래를 못 보게" 하는 방식으로 같은 효과를 냅니다. 논문도 "output embeddings are offset by one position"이라고 써서 정답을 오른쪽으로 한 칸 민다(shifted right) 점이 teacher forcing 입력과 같은 구조예요.

### 5.4 Table 1 — 왜 RNN 대신 Self-Attention인가 (§4)

| Layer Type | 층당 계산 복잡도 | 순차 연산 수 | 최대 경로 길이 |
|---|---|---|---|
| Self-Attention | O(n²·d) | **O(1)** | **O(1)** |
| Recurrent | O(n·d²) | O(n) | O(n) |
| Convolutional | O(k·n·d²) | O(1) | O(log_k n) |

- n: 문장 길이, d: 표현 차원
- **순차 연산 수 O(1) vs O(n)**: 병렬화 가능성의 차이. 우리가 질문한 "병렬 입력"의 이점이 여기 있어요.
- **최대 경로 길이 O(1)**: 문장 맨 앞 단어와 맨 끝 단어가 한 번의 attention으로 직접 연결됩니다. RNN은 n번 거쳐야 하므로 먼 단어의 정보가 희미해지는 문제(우리가 LSTM 노트북에서 본 병목)가 생깁니다.
- 대가: Self-Attention은 n²에 비례합니다. 논문도 "n이 d보다 작을 때 RNN보다 빠르다"고 조건을 답니다. 문장이 아주 길면 이 n²가 부담이 된다는 한계를 논문 스스로 언급해요 (restricted self-attention을 향후 연구로 제시).

### 5.5 §3.2.1 — 스케일링 √d_k (자세히)

> 질문: 식 (1)의 `√d_k`가 정확히 무엇인가? 강사님은 "Q와 K 내적 시 벡터의 길이/숫자의 개수"라고 답변하셨다.
> 결론: 강사님 말씀이 맞다. d_k는 Key(그리고 Query) 벡터의 차원 수, 즉 벡터 안에 들어 있는 숫자의 개수이고, √d_k는 그 개수의 제곱근이다. 내적 값을 이 수로 나눠서 크기를 줄이는 데 쓴다.

#### 5.5.1 d_k가 뭔지

Q와 K는 각 단어마다 하나씩 있는 벡터입니다. 논문은 d_model=512를 h=8개 헤드로 나눠서, 헤드마다 d_k = 512/8 = **64**를 씁니다(§3.2.2).

```
q = [q1, q2, ..., q64]     ← 숫자 64개  → d_k = 64
k = [k1, k2, ..., k64]
q·k = q1·k1 + q2·k2 + ... + q64·k64   ← 64개를 더함
```

식 (1)은 이 내적을 `√64 = 8`로 나눈 뒤 softmax에 넣는다는 뜻입니다.

```
score = (q·k) / √d_k  →  softmax → 가중치
```

#### 5.5.2 왜 나눠야 하나: 내적은 차원이 클수록 커진다

q, k의 각 숫자가 **평균 0, 분산 1인 임의의 값**이라고 가정합니다(논문 각주 4의 가정). 내적은 곱 d_k개를 더한 값입니다.

- 곱 하나(qᵢkᵢ)의 분산은 1입니다.
- 독립인 값 d_k개를 더하면 분산이 더해져서 **내적의 분산 = d_k, 표준편차 = √d_k** 가 됩니다.

직접 시뮬레이션한 결과입니다(무작위 벡터 2만 쌍, 평균 0·분산 1 정규분포).

| d_k | 내적의 표준편차 | √d_k로 나눈 뒤 |
|---|---|---|
| 4 | 2.0 | 1.0 |
| 64 | 8.0 | 1.0 |
| 512 | 22.5 | 1.0 |

차원이 커질수록 내적 값이 흩어지는 폭이 √d_k배로 커집니다. √d_k로 나누면 **d_k가 얼마든 표준편차가 1로 고정**됩니다. 이래서 d_k가 아니라 √d_k입니다. d_k로 나누면 너무 줄어들고, √d_k로 나누면 딱 1이 됩니다(표준편차는 분산의 제곱근이니까).

#### 5.5.3 값이 크면 왜 문제인가: softmax가 포화된다

softmax는 큰 값을 훨씬 크게 키웁니다. 점수가 ±20처럼 크면 가장 큰 쪽이 거의 1, 나머지는 거의 0이 됩니다. 이때 softmax의 기울기가 거의 0이라 역전파가 안 흘러서 학습이 멈춥니다(논문: "extremely small gradients").

같은 점수로 5개 단어에 대한 가중치를 만들어 본 결과입니다(점수는 무작위 q, 5개의 무작위 k로 계산).

| | 나누기 전 | √d_k로 나눈 후 |
|---|---|---|
| d_k=4 | [0.20, 0.01, 0.07, 0.69, 0.03] | [0.25, 0.05, 0.15, 0.46, 0.10] |
| d_k=512 | **[1.0, 0, 0, 0, 0]** | [0.50, 0.02, 0.13, 0.08, 0.27] |

d_k=512에서는 나누지 않으면 한 단어에만 가중치 100%가 몰립니다. 기울기를 나타내는 `max p(1−p)`도 0.0000이라 학습이 거의 안 됩니다. 나누면 가중치가 여러 단어에 적절히 퍼지고 기울기도 0.25로 살아 있습니다.

(표의 숫자는 난수 시드에 따라 달라지는 한 번의 예시입니다. 경향이 핵심입니다.)

#### 5.5.4 앞서 배운 내용과 연결

- 우리 노트북의 Keras `Attention`은 기본값이 `score_mode='dot'`이고 √d_k 스케일링이 없습니다. 우리가 쓴 128차원 정도에서는 큰 문제가 없었지만, Transformer는 차원이 크고 층도 깊어서 스케일링이 필요합니다.
- 논문은 스케일링이 없는 dot-product attention이 d_k가 클 때 additive attention(Bahdanau 방식)보다 못하다는 선행 연구를 인용합니다(§3.2.1, [3]). 그 보완책이 √d_k입니다.
- 위 4.5절 PE 내적 예(자기 자신과의 내적 32)에서도 차원이 늘수록 내적 크기가 커지는 현상을 볼 수 있습니다.

#### 5.5.5 한 문장 정리

**d_k = Q/K 벡터의 숫자 개수이고, 내적은 그 개수만큼 더하느라 값이 √d_k배 커지니, 미리 √d_k로 나눠서 softmax가 한쪽으로 쏠리지(포화되지) 않게 한다.**

강사님께 확인해 보고 싶다면: "내적의 분산이 d_k라서 √d_k로 나누는 건가요?" (분산 = d_k 부분은 논문 각주 4, 5.5.3절의 표는 직접 돌린 결과)

### 5.6 §3.2.2 — Multi-Head Attention
- h = 8개 헤드, d_k = d_v = d_model/h = 64. "서로 다른 표현 부분공간에서 서로 다른 위치의 정보를 동시에 본다."
- 헤드 1개는 최고 설정보다 BLEU 0.9 낮고(Table 3 (A)), 헤드가 너무 많아도 성능이 떨어집니다.
- PE와의 관계: 어떤 헤드는 "바로 앞 단어"를, 다른 헤드는 "문장 앞쪽의 동사" 같은 서로 다른 위치 관계를 학습할 수 있습니다. (이 연결은 제 해석이며 논문의 부록 attention 시각화에서 헤드마다 다른 역할을 하는 모습이 보인다고 합니다. §4 마지막 문단)

### 5.7 §5.4 — 정규화 방식과 PE에 걸리는 dropout
- 임베딩과 PE의 합에도 dropout(P_drop = 0.1)을 적용합니다. (§5.4 Regularization: "we apply dropout to the sums of the embeddings and the positional encodings")

## 6. 정리: 흔한 오해 체크

| 오해 | 실제 |
|---|---|
| "병렬로 넣으니까 순서를 알 수 없다" | **PE가 없으면** 맞는 말이에요. 그래서 PE를 더합니다. |
| "PE는 학습되는 값이다" | 논문의 sin/cos 방식은 **학습 파라미터가 없는 고정 함수**입니다. (학습형도 가능하고 성능은 비슷) |
| "sin/cos로 각 위치를 고유하게 만든다" | 맞지만 더 중요한 이유는 **상대 거리를 회전(선형변환)으로 표현**할 수 있다는 것(4.4절). |
| "PE를 임베딩 뒤에 이어 붙인다" | **더합니다.** 차원이 같아야 하는 이유. |
| "한 위치의 PE는 하나의 숫자" | **d_model 차원 벡터**입니다. (논문 512차원) |
| "인코더에만 PE가 있다" | 논문은 **인코더와 디코더 입력 모두**에 더합니다. (§3.5: "at the bottoms of the encoder and decoder stacks") |

## 7. 직접 확인해 볼 코드 (선택)

```python
import numpy as np

def positional_encoding(max_len, d_model):
    P = np.zeros((max_len, d_model))
    for pos in range(max_len):
        for i in range(d_model // 2):
            w = 1 / 10000 ** (2 * i / d_model)
            P[pos, 2 * i]     = np.sin(pos * w)   # 짝수 차원: sin
            P[pos, 2 * i + 1] = np.cos(pos * w)   # 홀수 차원: cos
    return P

print(positional_encoding(5, 4).round(4))   # 3.2절 표와 같은 값이 나옵니다
```
